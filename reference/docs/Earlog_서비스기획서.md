# Earlog 서비스 기획서

원본(편집용): https://claude.ai/artifact/LPSahR4vwNbNmgoHnNn8Jf

## 한눈에 보기

Earlog는 그날 들은 노래 한 곡을 장면 사진, 분위기, 짧은 이야기와 함께 남기고, 쌓인 기록을 달력과 가수별·장르별 보관함으로 다시 꺼내 보는 음악 기록 웹서비스예요.

| 항목 | 내용 |
| --- | --- |
| 서비스 이름 | Earlog (이어로그). ear(귀) + log(기록) = 귀로 들은 노래를 기록한다 |
| 슬로건 | Log what you hear |
| 한 줄 소개 | 하루 한 곡씩 쌓이는 나만의 월간 플레이리스트 |
| 형태 | 웹서비스 (데스크톱 1440px 기준 디자인, 모바일 대응 예정) |
| 화면 수 | 11개 (랜딩, 로그인, 회원가입, 달력, 타임라인, 기록 쓰기, 상세, 삭제 확인, 프로필, 보관함 2종) |
| 프로젝트 | 빌드업 프로젝트. 기본 뼈대 Picstory에 보관함 기능을 더해 확장 |

## 문제와 타깃

기분에 맞는 노래를 찾아 듣는 사람일수록, 그때 좋았던 노래를 나중에 잊어버려요.

**타깃 사용자**
- 그날 기분에 맞는 노래를 찾아 듣는 20대
- 출퇴근길, 운동, 공부처럼 상황마다 듣는 노래가 다른 사람

**겪는 문제**
- 좋았던 노래를 다시 찾으려면 기억에 기대야 해요.
- 재생 기록에는 "그날 왜 그 노래였는지"가 남지 않아요.
- 노래와 그때의 장면, 기분이 따로 흩어져서 한데 모아 볼 곳이 없어요.

## 해결 방법

하루에 딱 한 곡만, 그날의 장면 사진과 분위기를 붙여 남기게 해요.

| 원칙 | 왜 이렇게 하나요 |
| --- | --- |
| 하루 한 곡 | 여러 곡을 고르지 않아도 돼서 매일 부담 없이 남길 수 있어요. |
| 장면 사진 1장 | 노래를 들은 그 순간이 커버가 돼서, 노래와 그날이 함께 기억나요. |
| 분위기 색 | 다섯 가지 분위기마다 색이 정해져 있어서, 한 달이 어떤 색이었는지 한눈에 보여요. |
| 자동 정리 | 쌓인 기록이 가수별, 장르별로 저절로 모여요. |
| 나만 보기 | 기록은 로그인한 본인만 볼 수 있어요. |

## 주요 기능

| 단계 | 기능 | 설명 |
| --- | --- | --- |
| 기록하기 | 오늘의 노래 기록 | 사진, 곡명, 가수, 지역·장르, 분위기, 이야기, 상황 태그. 수정과 삭제도 돼요. |
| 보기 | 달력 | 기록한 날이 분위기 색 커버로 채워져요. |
| 보기 | 타임라인 | 날짜순 목록, 검색, 장르 필터. |
| 보기 | 기록 상세 | 하루 기록을 크게, 이전·다음, 같은 가수의 다른 기록. |
| 다시 찾기 | 보관함 (추가 기능) | 가수별, 장르별. 장르는 지역(K·J·GLOBAL)으로 한 번 더 걸러요. |
| 돌아보기 | 통계 | 이번 달 기록 수, 연속 기록, 많이 들은 장르와 가수, 분위기 분포. |
| 계정 | 로그인, 나만 보기 | 이메일·카카오 로그인. 내 기록은 나만 봐요. |

## 화면 구성과 흐름

| 번호 | 화면 | 들어가는 것 |
| --- | --- | --- |
| S0 | 랜딩 | 앨범 진열대, 하루 기록 예시, 보관함 소개, 한 달의 색, 시작하기 |
| S1 | 로그인 | 이메일·비밀번호, 카카오 로그인, 회원가입 링크 |
| S2 | 회원가입 | 이메일, 비밀번호, 비밀번호 확인, 닉네임 |
| S3 | 달력 (메인) | 월 이동, 분위기 색 커버 달력, 어제의 한 곡, 이번 달 리포트 |
| S3-1 | 타임라인 | 이번 달 플레이리스트, 검색, 장르 필터, 날짜순 카드 |
| S4 | 기록 쓰기·수정 | 날짜, 사진, 곡명, 가수, 지역·장르, 분위기, 이야기, 상황 태그 |
| S5 | 하루 상세 | 큰 사진, 기록 전체, 이전·다음, 같은 가수의 다른 기록, 수정·삭제 |
| S5-1 | 삭제 확인 | 삭제할 기록 미리보기 모달 |
| S6 | 프로필·통계 | 총 기록, 연속 기록, 가수 순위, 분위기·장르 분포 |
| S7 | 보관함 — 가수별 | 가수 목록(곡 수 순·이름순), 선택한 가수의 곡 목록 |
| S7 | 보관함 — 장르별 | 장르 타일, 지역 필터, 선택한 장르의 커버 목록 |

흐름: 랜딩 → 로그인(↔ 회원가입) → 달력(메인). 사이드바로 타임라인·기록 쓰기·보관함·프로필 이동. 달력·타임라인·보관함에서 기록을 고르거나 쓰기에서 저장하면 하루 상세 → 삭제 시 삭제 확인 모달. 상세의 수정 버튼은 기록 쓰기 화면을 다시 열어요.

## 기록 데이터

기록 하나는 9개 항목. 한 사람은 하루에 하나만, 같은 날짜로 다시 저장하면 수정.

| 항목 | 입력 방식 | 비고 |
| --- | --- | --- |
| 날짜 | 날짜 선택 | 하루 1개 |
| 사진 | 업로드 1장 | 그 노래를 들은 장면. 커버가 돼요 |
| 곡명 | 입력 | |
| 가수 | 입력 | 가수별 보관함에 사용 |
| 지역 | 선택 1개 | K (국내), J (일본), GLOBAL (해외) |
| 장르 | 선택 1개 | 발라드, 댄스, 힙합, R&B, 인디, 록, OST, 기타 |
| 분위기 | 선택 1개 | 잔잔, 설렘, 신남, 집중, 울적 |
| 이야기 | 입력 | 왜 오늘 이 노래였는지 몇 줄 |
| 상황 태그 | 자유 입력 여러 개 | #출근길, #새벽, #운동 등 |

예) 아이유 「밤편지」 → K + 발라드 + 잔잔 + #새벽

보관함, 월 리포트, 프로필 통계는 따로 저장하지 않고 기록 목록에서 계산.

- [ ] 디자인 화면의 장르 표기(K-POP, J-POP, 발라드… 7개)를 위 지역 + 장르 기준으로 맞추기

## 디자인 방향

| 항목 | 결정 |
| --- | --- |
| 스타일 | v2 음악 앱 스타일. 왼쪽 사이드바, 커버 중심의 카드와 목록 |

| 화면 크기 | 1440px 데스크톱 기준 |

## 개발 계획

| 단계 | 할 일 | 상태 |
| --- | --- | --- |
| 1 | 기획과 화면 목록 정리 | 완료 |

| 4 | 공통 요소: 사이드바, 버튼, 커버 카드, 태그 | 다음 |
| 5 | 화면 마크업 (아래 순서) | |

| 7 | 자동 정리 기능: 보관함, 월 리포트, 통계 | |
| 8 | 로그인 연결 | |
| 9 | 점검과 배포 | |

화면 제작 순서: S3 달력 → S4 기록 쓰기 → S5 상세·S5-1 삭제 → S3-1 타임라인 → S7 보관함 → S6 프로필·통계 → S1 로그인·S2 회원가입 → S0 랜딩

기술: React(Vite)와 React Router로 바로 시작. 데이터는 당분간 브라우저 localStorage에 저장하고, 서버와 배포 방식은 미정.

- [ ] 서버·데이터 저장 방식과 배포 방법 정하기
- [ ] 노션 기획과 디자인의 차이 정리: 랜딩 화면 추가, 보관함 구성, 상단 메뉴 대신 사이드바
